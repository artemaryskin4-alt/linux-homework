# hw6 — regex_practice

Практические задания по основам Linux: работа с регулярными выражениями,
`grep`, `awk`, `find` и bash-скриптами. Все скрипты снабжены справкой (`-h`),
проверены на граничных случаях и отлажены — по пути выловлено несколько
классических ловушек bash (см. раздел «Найденные и исправленные ошибки»).

## Структура

```
hw6/regex_practice/
├── task_regex_email.sh    # поиск email с заданным доменом (.ru и др.)
├── find_genome.sh         # поиск файлов по маскам имени + статистика
├── find_minus_genes.sh    # фильтр генов в GFF по цепи, длине и первой букве
├── find_IP.sh             # поиск IP-адресов: активные сессии и логи
├── emails.txt             # тестовый файл с пограничными случаями email
├── genes.gff              # тестовый GFF (разделители — пробелы)
└── test_genome/           # тестовые файлы для find_genome.sh
```
## Скрипты
### 1. task_regex_email.sh

Поиск email-адресов с заданным доменом первого уровня (по умолчанию `.ru`).

Регулярка:

```
[a-zA-Z0-9._%+-]+@[a-zA-Z0-9-]+(\.[a-zA-Z0-9-]+)*\.(DOMAIN)(?![a-zA-Z0-9.-])
```

Хвостовой негативный просмотр `(?![a-zA-Z0-9.-])` отсекает ложные
срабатывания вида `site.rur` и `site.ru.com`.

Режимы и переменные окружения:

```bash
./task_regex_email.sh emails.txt              # все совпадения
cat file.txt | ./task_regex_email.sh          # или через stdin
DOMAIN=su ./task_regex_email.sh emails.txt    # другой домен первого уровня
COUNT_ONLY=1 ./task_regex_email.sh emails.txt # только количество вхождений
UNIQUE=1 ./task_regex_email.sh emails.txt     # только уникальные адреса
./task_regex_email.sh -h                      # справка
```

Проверено на граничных случаях (см. `emails.txt`): `.RU` в верхнем регистре
(регистронезависимый поиск `-i`), хвост `.ru123`, `.ru.com`, точка/запятая/
скобки после адреса, домен короче двух символов, отсутствие `@`,
кириллический домен.

## Тестовые данные

`emails.txt` содержит по одной строке на каждый граничный случай:

| Тип | Пример | Результат |
|-----|------- |---------  |
| валидный адрес | `user1@mail.ru` | находится |
| составной поддомен | `valid@sub.domain.ru` | находится |
| домен в верхнем регистре | `admin@yandex.RU` | находится (`-i`) |
| другой домен | `test@google.com` | не находится |
| прилипший хвост | `user@mail.ru123` | срезается по границе |
| псевдодомен | `user@mail.rur` | не находится |
| вложенный домен | `invalid@mail.ru.com` | не находится |
| без `@` | `no-at-sign.ru` | не находится |
| без локальной части | `@no-user.ru` | не находится |
| слишком короткий домен | `user@mail.r` | не находится |
| пунктуация после адреса | `user@mail.ru,` | адрес срезается корректно |

### 2. find_genome.sh

Поиск файлов, в имени которых встречаются `genome` и/или `GCA`.

- режим по умолчанию — файлы с любым из слов;
- `--and` — только файлы, где есть оба слова;
- `--each` — раздельные списки по каждому слову;
- в конце каждого списка — статистика: количество файлов и суммарный размер в байтах.

```bash
./find_genome.sh test_genome --each
```
### 3. find_minus_genes.sh

Фильтр строк в GFF-файле: выбирает гены, которые

- лежат на минус-цепи (`-`);
- имеют название длиннее 3 символов;
- название не начинается с A, Z, H (в любом регистре).

Разделитель колонок — `[ \t]+` (пробелы и табуляции). Название берётся
из атрибутов `Name=` или `gene=` девятой колонки.

```bash
./find_minus_genes.sh genes.gff          # только минус-цепь
./find_minus_genes.sh genes.gff --both   # плюс-цепь для сравнения
```

Пример вывода:

```
--- Минус-цепь (по заданию) ---
chr1 100 500 brca1 -
chr1 2600 3000 mnop -
```

## Найденные и исправленные ошибки

Полезные грабли, на которые наступили при отладке:

1. **`eval` с переменными** — небезопасно и непредсказуемо; заменено на обычный вызов `find`.
2. **CRLF-концы строк** — скрипт, сохранённый с Windows-переводами строк, не запускается; лечится `dos2unix` или `sed -i 's/\r$//'`.
3. **Потерянная функция при копипасте** — `/dev/null`-тихое «исчезновение» кода; лечится пересозданием файла через heredoc.
4. **Жадная регулярка** — `[^;]+` захватывал лишнее; потребовалось уточнение границ.
5. **`((count++))` с `set -e`** — постинкремент возвращает 0 → код выхода 1 → скрипт молча умирает на первой итерации; заменили на `count=$((count + 1))`.
6. **awk без файла-аргумента** — ждёт stdin и «зависает»; в функции забыли передать `"$GFF"`.
7. **Диапазон `a-z` в символьном классе** — `[AZHa-zh]` означает «вся строчная латиница», а не «a, z, h»; заменено на `tolower(val) !~ /^[azh]/`.
8. **«Тихий» sed** — паттерн `(?!\.)` в команде sed не экранировал литеральный обратный слэш: sed отработал без ошибки и ничего не заменил. Правильно: `s/(?!\\\.)/.../ ` или perl с `\Q...\E`.

## Требования

- bash 4+;
- GNU grep с поддержкой `-P` (PCRE);
- `awk` (проверено на mawk — стандартном для Ubuntu/WSL);
- `stat`, `find`, `sort`, `uniq`.

Проверялось в WSL (Ubuntu).
